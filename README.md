## Key Mechanisms (Do Not Remove or Soften)

### 1. Falsification Test (Decision Log)
Every decision must answer:  
**"What result in the next 7 days would prove this was the wrong move?"**

This is the single highest-leverage feature. It kills romanticized bad strategy faster than any other mechanism.

### 2. 90-Minute Block Protocol
- One protected block per day minimum.
- Phone on Do Not Disturb.
- One objective only: execution or logging why execution failed.
- No research. No planning. No "getting organized."
- End of block = immediate entry in Proof Archive or Outreach Log.

### 3. Proof Archive
If it isn't logged with a link, screenshot, or timestamp, it didn't happen. Visibility and cash require receipts.

### Database 1: Outreach Log

**Properties (create exactly in this order):**

| Property Name          | Type          | Purpose |
|------------------------|---------------|--------|
| Date                   | Date          | When the move was made |
| Target Name / Company  | Text          | Who you contacted |
| Channel                | Select        | X DM / Email / Text / LinkedIn / Other |
| Message Sent           | Text          | Paste the actual message (no summaries) |
| Response Received      | Select        | Yes / No / Pending |
| Response Details       | Text          | Exact reply or notes |
| Next Action            | Text          | Specific, time-boxed next step |
| Proof Link             | URL           | Screenshot, thread, or email proof |
| Outcome                | Select        | Meeting booked / Cash / Intro / Kill / No reply after 3 touches |
| Constraint Overcome    | Text          | Which barrier this attack targeted |
| Time Invested (min)    | Number        | Actual minutes spent |

**Recommended Views:**
- Active (Outcome is empty)
- This Week
- By Channel
- High Response Rate (filter Response Received = Yes)

---

### Database 2: Decision Log

**Properties:**

| Property Name          | Type          | Purpose |
|------------------------|---------------|--------|
| Timestamp              | Date + Time   | When decision was made |
| Situation / Trigger    | Text          | What forced the decision |
| Options Considered     | Text          | Minimum 3 options listed |
| Chosen Move            | Text          | What you actually did |
| Rationale              | Text          | Why this over the others given current constraints |
| Falsification Test     | Text          | "What result in 7 days proves this was wrong?" |
| Actual Outcome         | Text          | Fill in later (required) |
| Lesson Captured        | Text          | What the outcome taught you |
| Proof Attached         | Files & Media or URL | Evidence of execution or result |

**Recommended Views:**
- This Week
- Needs Outcome Update (Actual Outcome is empty)
- High-Impact (filter by Falsification Test length or manual tag)

---

### Database 3: Proof Archive

**Properties:**

| Property Name              | Type          | Purpose |
|----------------------------|---------------|--------|
| Date Shipped               | Date          | When the artifact went live |
| Artifact Name              | Text          | What you shipped |
| Type                       | Select        | Code / Doc / Thread / Outreach / Product / Other |
| Link or File               | URL or Files  | The actual deliverable |
| Visibility Gained          | Number        | Impressions, replies, profile visits, etc. |
| Revenue Generated ($)      | Number        | Direct cash from this artifact |
| Constraint It Attacked     | Text          | Which zero-budget barrier this bypassed |
| Notes                      | Text          | Context or next leverage |

**Recommended Views:**
- This Month (board or list)
- By Type
- Revenue Positive

### Supporting Pages (create as normal pages, not databases)

**1. 90-Minute Block Protocol** (paste this exact text)

```
PROTECTED 90-MINUTE BLOCK RULES

Every day has minimum ONE protected 90-minute block.

Non-negotiable rules:
1. Phone on Do Not Disturb. Chromebook only. No exceptions.
2. Single objective that produces either proof or cash movement.
3. If you break early, you must immediately log the exact reason + cost in Decision Log.
4. End of block = immediate Proof Archive or Outreach Log entry.
5. "Research" and "planning" are banned inside the block. Only execution or logging failure.

This is not a suggestion. This is the operating system.
```

**2. Kill List** (simple page with toggle list + linked database)

Create a database called Kill List with properties:
- Item (text)
- Date Killed (date)
- Reason (text)
- What Replaced It (text)

Rule: Anything that produced zero proof or cash in the last 7 days goes here.

**3. Constraint Inventory** (page)

Exact sections:

```
WHAT I ACTUALLY HAVE RIGHT NOW
- Chromebook + phone
- Specific skills (list yours)
- Existing relationships (list)
- Public data access
- Time blocks I can protect
- Refusal to quit

WHAT THE WORLD CLAIMS I NEED
- Capital
- Credentials
- Stable housing
- Vehicle
- Professional network
- Emotional safety net

GAP ANALYSIS
Which gaps can be bypassed with better moves?
Which gaps must be attacked directly with proof?
```

**4. Weekly Review Template** (duplicate this page every Sunday)

Sections:
- Proofs shipped vs planned
- Response rate reality check
- Cash moved this week
- Kills executed
- One decision whose falsification test needs updating
- One new constraint attack for next 7 days
- Next Sunday's protected block schedule
